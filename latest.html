PROTOTYPE THIS WEEKENDgreen · pure software · no capital · you already understand agentic code from the inside

API providers announce their breaking changes instead of just applying them

The problem
When an API changes, every customer hand-edits their own codebase to keep up. The infrastructure to fix this automatically now exists — agentic coding tools proved companies will grant external tools access to their repos if the value is there — but the layer that connects an API provider to its customers' code does not. Two launches today show the access-grant norm hardening: Greptile now pushes bug detection beyond code review with a repo-aware model, and Infisical raised $40M (see §1) precisely so agents can act on your services without holding the keys. The rails are being laid; the obvious thing on top of them is not built.
Who says it's hard
Y Combinator, Requests for Startups — the RFS written by a founder who worked with 50+ API vendors. Two years ago nobody would grant an external tool write access to their repo; Claude Code, Devin and Greptile normalised it, and the window opened recently enough that nobody has built the layer yet.
Why it's still open
Trust and blast radius. Pushing an automated change into a stranger's repository means getting the migration exactly right, proving it's safe, and earning write access — the same three walls Renovate hit for dependency bumps, now for the much harder case of semantic API changes where the meaning, not just the version string, moved.
Who's already trying
Greptile, Ellipsis, and Renovate — but Renovate only bumps dependency versions, not the API semantics underneath. Nobody owns the provider→customer migration channel for breaking changes.
Your angle
Pure software, no capital, and you already understand agentic code editing from the inside because you live in Claude Code. It is narrow enough to prototype in a weekend — which is exactly what §6 turns into a two-hour exercise today.
Research path
  1. Pick one API with frequent breaking changes (Stripe, Twilio) and read two years of its changelog — feel how often, and how much, the meaning moves.
  2. Write the migration codemod for a single breaking change by hand with an AST tool. Do the work before you automate it (§6 is this step).
  3. Read Renovate's architecture docs on how an automated PR against a stranger's repo earns enough trust to get merged. Trust is the product, not the diff.
FILE, DON'T STARTred — frontier cryptography, standards bodies, a decade of global migration; learn the vocabulary only

AI-accelerated math is coming for the encryption the internet runs on

The problem
The public-key cryptography protecting banking, messaging and identity rests on a bet that certain math problems stay hard. AI systems are now making genuine mathematical progress — and the deeper exposure underneath is that almost no production system can swap its cryptographic primitives quickly (“crypto-agility”), so a break wouldn't be a patch, it would be a multi-year migration nobody has rehearsed.
Who says it's hard
Vitalik Buterin (take AI-accelerated math seriously, floating a “bunker mode”) and Scott Aaronson (“The Mathocalypse”), set against this week's evidence that the capability is real: OpenAI scooped human researchers on a million-dollar quantum-math problem, dueling OpenAI/Anthropic proofs “astounded scientists”, and the Classification of Finite Simple Groups was formalised in Lean (§4). YC's own RFS and DARPA both circle the adjacent “AI for math” frontier.
Why it's still open
It needs frontier cryptography, standards bodies and coordinated global migration at once. Post-quantum standards exist on paper; getting the world to adopt crypto-agility before a break rather than after is a decade-long coordination problem, not a product.
Who's already trying
NIST (post-quantum standards), Cloudflare, Google, Apple, PQShield. All are institutions with standards power and distribution — which is the point: this is a standards game, not a building game.
Your angle
Red, and honestly so — a standards-and-PhD problem, not a weekend build. File it to recognise one narrow, boring slice if it ever appears: tooling that inventories which cryptographic primitives a codebase actually depends on is the unglamorous first step of any migration, and that part is just software. Learn the vocabulary; do not start here.
Research path
  1. Read Scott Aaronson's “The Mathocalypse” for the honest state of the threat, then today's Verge piece on why researchers distrust the way these results are being dropped.
  2. Skim NIST's post-quantum standards to see what “the answer” already looks like on paper.
  3. Notice the cheap adjacent slice: crypto-agility tooling — “what am I even using, and where” — is software even when the cryptography is not.

Agent infrastructure · the picks-and-shovels of the agent era, funded

Infisical raised $40M to keep AI agents away from the passwords they'd otherwise hold

$40M Series B · $600M valuation · led by Elad Gil (Gradient, YC in) · 30,000+ GitHub stars · 1,300+ orgs · cash-flow positive · Infisical · Forbes · Techmeme

What they do
Infisical is an open-source secrets manager — it stores and syncs the API keys, certificates and credentials an app needs, so they stop living in a .env file someone pastes into Slack. The new product, Agent Vault, extends that to AI agents: the agent sends a request toward an approved service, and a forward proxy attaches the real credential on the way out — so the agent can act on your systems without ever holding the password itself.
The mechanism
The thesis is that software volume is exploding and every new program is a new machine identity that needs a credential. Their own words: “more software also means more infrastructure, machine identities, credentials, and certificates that need to be secured.” The brokered-proxy design is the clever part — it turns “trust the agent with the key” into “let the agent make a request and we apply the key,” which is auditable and revocable in a way a leaked key never is.
The founders
Vlad Matsiiako, Maidul Islam and Tuan Dang met as students at Cornell and went through Y Combinator (W23). The unfair advantage is boringly specific: they built a secrets manager a developer could adopt in an afternoon and kept the core MIT-licensed, so it spread to 30,000 stars and 1,300 orgs (LG, Wise, the US Government) before agents existed. They already owned the credential plane; agents just became a new thing that needs it.
The bear case
Secrets management is a crowded, consolidating market — HashiCorp Vault, AWS/GCP secret managers, Doppler — and the agent-credential story is new enough that Agent Vault is still labelled “preview.” If the cloud giants ship a good-enough broker inside their own agent runtimes, an independent layer gets squeezed. Open-source adoption is not revenue, and a $600M valuation prices in the agent thesis landing.
What it means
This is the clearest “sell shovels” story you'll see all month, and it validates today's §0-green from the inside: the agent era is being plumbed right now, by small teams who owned an unglamorous primitive first. Two transferable moves — (1) start with a boring tool developers adopt themselves, then ride the next shift (agents) into a bigger market; (2) notice that the whole company is one design insight (“broker the credential, don't hand it over”). It's also free to study: the core is open (§8).
Reindustrialisation · capital flowing to atoms, not just bits

Re:Build raised $2.1B to rebuild American hard-tech manufacturing — “America's answer to Shenzhen”

$2.1B · led by General Catalyst + JPMorganChase Strategic Investment Group · 2,100+ employees · 2.4M sq ft · spun out Slate Auto ($1.4B+ raised, Bezos-backed) · Re:Build · TechCrunch

What they do
Re:Build is a holding company for American hard-tech manufacturing: it owns a network of engineering and factory businesses, and uses them to incubate and spin out industrial startups. Its most famous spinout is Slate Auto, the stripped-down cheap EV truck it conceived in 2022 and spun out in 2023 — which has since raised $1.4B+ including from Jeff Bezos's family office.
The mechanism
The structure is the story. This isn't a classic venture round — it's led by General Catalyst and JPMorgan's Strategic Investment Group (the arm running its “Security and Resiliency” initiative), capital aimed at building physical capacity and launching industrial companies off a shared manufacturing base. The bet: owning real factories, tooling and 2,100 people is the moat, and new product companies can be launched off that base far cheaper than from zero. CEO Jeff Wilke — former Amazon worldwide-consumer CEO, the operator who built Amazon's fulfilment machine — frames it as fixing “an economic failure and a national security risk.”
The founders
Jeff Wilke ran Amazon's consumer business for two decades; the access he had that others didn't is twenty years of knowing, operationally, exactly how physical throughput is engineered and financed at scale. Re:Build is that knowledge pointed at American industry instead of Amazon's warehouses.
The bear case
Manufacturing is brutally capital-intensive and low-margin; “America's answer to Shenzhen” is a slogan Shenzhen earned over 30 years of dense supplier networks that money alone can't reconstitute. A holding company that both operates factories and spins out startups is hard to value and harder to focus. Slate Auto is one hit; the model needs several, and EV demand is wobbling (§9).
What it means
This is the reindustrialisation thesis made concrete, and it sits one domain from your tiltrotor and from the “American defense” problem you've been circling: the capital is now explicitly flowing to US-made atoms, backed by a bank's national-security arm. The transferable lesson is the holding-company move — build a shared capability once (factory, tooling, or in your case a build-log and a working airframe) and launch several bets off it, rather than betting everything on one product. Watch how Slate priced “cheap and simple” as a feature; that's the opposite of the spec-sheet arms race.
World models · the design-and-film lane, and the training data for robots

DeepMind's Genie 4 generates a world you can steer — and now hear

real-time interactive worlds · native audio (a first) · Gemini 3.8 Flash in the loop · 792 HN points · DeepMind · TechCrunch

What they do
Genie 4 is a “world model”: give it a prompt or an image and it generates an interactive, photorealistic environment you can move through in real time — now with sound, and steerable with plain language (change the weather, move the camera, drop in an object) while the scene stays coherent. It's the first real-time world model to generate audio natively.
The mechanism
Two systems run together: a world model does the pixel-level simulation, and Gemini 3.8 Flash sits “in the loop” — watching the scene, breaking your goal into steps, and steering the simulation so it keeps progressing coherently instead of dissolving into noise. The hard part of world models has always been temporal consistency (the world forgetting what was behind you); putting a reasoning model in charge of continuity is the move.
The founders
This is Google DeepMind, not a startup — so the relevant “unfair advantage” is the Gemini stack it's built on. Worth noting because it tells you where the frontier labs think the puck is going: not just text, but simulated worlds as a product surface.
The bear case
Demos of world models have outrun reality before; DeepMind's blog names no resolution, no session length, and no public access yet, so “real-time” and “photorealistic” are claims until you can drive one yourself. And a parallel arXiv line this week asks pointedly about the limits of what latent world models actually learn.
What it means
DeepMind names filmmaker pre-visualisation as a use case outright — that is your lane, directly: the ability to block out a scene, steer a camera and hear it, before a single real frame is shot. It also names robotics-training environments, which is the quiet commercial engine (the same reason NVIDIA is shipping sim-ready asset datasets this week). The opening for you isn't competing with DeepMind — it's being early to use steerable worlds as a pre-viz and simulation tool for your own hardware and film work while almost nobody has the instinct for it yet.

The Remake

one evidenced candidate · never more
Same tool, unbundled — ship the one feature they installed it for, and keep it honest

The free SEO bar that does the one check Moz and SEO Minion put behind a login

The incumbent
MozBar (the decade-old default SEO toolbar, ~2,000 Chrome reviews) and SEO Minion (200,000+ installs). Both were the free answer to “best SEO extension,” and both moved their core behind a login or a bundled subscription — MozBar's Domain/Page Authority now needs a Moz account, SEO Minion is gated behind Keywords Everywhere's paid plan.
The complaint
The ratings collapse is recent, sharp and traceable to that one decision. MozBar sits around 3.3 stars lifetime but 1.59 across its last 100 reviews; SEO Minion is 4.0 lifetime, 1.65 across its last 100. A real MozBar reviewer: “It forces me to login so often. It doesn't show all data (I am a paid — $179).” And another: “The previous Moz bar was excellent. This one is just…” The whole recent-review stream is one sentence: it used to be free, it isn't now, and there's no way to just check the thing.
Which remake
Same tool, unbundled. Don't rebuild Moz. Ship a Chrome extension that does the single thing people installed those bars for — an instant, no-login on-page SEO + authority-style snapshot on any page — using open or your own computed metrics (you can't copy Moz's proprietary DA, and you shouldn't pretend to). The pitch is the exact axis of the complaint: no account wall, no bundle, the check works the second you install it.
The buyer
SEO freelancers, small agencies and affiliate/blog operators who today either suffer the login or pay $179/yr for Moz Pro or $72/yr for Keywords Everywhere just to keep a check they used to get free. Free core for distribution; a flat paid tier for the things agencies actually need in volume — bulk pages, CSV export, SERP snapshots. Buyer and user are the same person, and the Chrome Web Store is the distribution.
Why him
Two of your edges at once. Taste: SEO toolbars are famously ugly, cramped and hostile — a clean, legible bar is a real differentiator in a category that treats design as an afterthought. And trust: the entire wound here is users feeling baited, so an honest, visible “this stays free” promise is the product, and honesty is a design decision competitors keep getting wrong.
First step
Today: install both MozBar and SEO Minion, screenshot the exact moment each one demands a login, and list the two or three checks you hit the wall on. Then build the ugliest possible Chrome extension that performs just one of them (say, pull the page's title/meta/H-tags and outbound-link count) with zero login, and put a single honest line on the store listing: “the check you installed MozBar for, without the account wall.” (Kill-filter check: the tempting version — “a full Moz/Ahrefs competitor” — fails: it needs a proprietary link-index worth hundreds of millions to build. The unbundle passes all five: useful the second it's installed, buyer = user with budget, runs unattended, not ad-supported consumer, and three payers are quoting their $179 bill in the review thread above.)

Skill

day 27

Write a codemod that auto-applies one API breaking change — today, in two hours

~2 hours · free · produces: a working codemod + first-hand feel for exactly where today's §0-green is hard

Today's §0-green is “API providers announce breaking changes instead of applying them.” The only way to understand that problem is to do the smallest possible version of it by hand. Pick one API you know (Stripe is ideal — its changelog is public and precise), find one breaking change in its history, and write a transform that rewrites real code from the old shape to the new one automatically. Use an AST-based tool, not regex: ast-grep is the fastest to pick up, and jscodeshift is the JavaScript standard. Point it at a toy file that uses the old API and make it emit the new one.

Keep a running note of every place it gets ambiguous: where the change wasn't a simple rename, where you needed to understand intent and not just syntax, where you had to guess. That note is the product. Every ambiguity you hit is the exact reason nobody has automated this yet — and the §0-green opportunity is to make those ambiguities tractable. You'll finish knowing, in your hands rather than in theory, why “just codemod it” is harder than it sounds and where the real moat (trust in an automated PR against a stranger's repo) lives.

Free resources: ast-grep's guide (the clearest mental model of structural search-and-replace) and Stripe's API changelog — a two-year archive of real breaking changes to pick your first target from.
